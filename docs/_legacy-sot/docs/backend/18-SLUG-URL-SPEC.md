# Public URL and Slug Specification

## Canonical public URL

```text
https://kartunamadigital.id/{slug}
```

No `/c/` prefix is used.

## Starter random slug

Format:
- length: 7 characters;
- alphabetic only;
- character set: `abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ`;
- case-sensitive;
- generated with a cryptographically secure random generator;
- generated by backend only;
- immutable while the card remains Starter;
- unique based on binary/case-sensitive comparison.

Example:
`aBcDeFg`

### Entropy and collision handling

The generator must:
1. generate a seven-character code;
2. query for exact case-sensitive collision;
3. retry within a bounded loop;
4. fail safely if a unique code cannot be obtained.

The database/index must preserve case sensitivity for Starter slug uniqueness.

## Basic/Pro custom slug

- Editable from card settings.
- Lowercase canonical format is recommended.
- Allowed characters: lowercase letters, digits, and hyphen.
- Length: 3–100 characters.
- Leading/trailing hyphen forbidden.
- Consecutive hyphens normalized or rejected.
- Reserved words forbidden.
- Availability check required.
- User must explicitly save the slug.

Examples:
- `ar081234567890`
- `arwan-prabowo`
- `arwan-sales`

## Default suggestion algorithm

Inputs:
- `full_name`
- `mobile_phone`

Process:
1. Normalize name to letters.
2. Take the first two alphabetic characters from the first name.
3. Lowercase them.
4. Normalize phone to digits only.
5. Preserve the local leading zero when the user entered an Indonesian local number.
6. Concatenate without separator.
7. Validate and check availability.
8. If unavailable, append a short numeric suffix.

Example:

```text
Arwan Prabowo
0812-3456-7890
-> ar081234567890
```

Fallback:
- Name shorter than two letters: use all available letters plus generated letters.
- Phone unavailable: use two name letters plus a short random numeric suffix.
- Collision: `ar0812345678902`, then another safe suffix.

## Privacy notice

A phone-based suggestion exposes the mobile number inside the public URL.
The UI must clearly state this before saving and provide alternative suggestions that do not contain a phone number.

The suggestion is a convenience, not a requirement.

## Redirect and history

MVP behavior:
- changing a Basic/Pro slug invalidates the old canonical URL;
- QR cache is regenerated for the new slug;
- old-slug redirect history is not guaranteed unless implemented later.

The UI must warn the user that previously distributed links and QR images may stop working.
